# omarchy-setup

Snapshot of this machine's customizations to a default [Omarchy](https://omarchy.org/)
install, plus a script to reapply them (fully or selectively) on a fresh
Omarchy PC.

## What's captured

Compared against `/usr/share/omarchy/default/`, `/usr/share/omarchy/config/`,
and the ISO's default package list (`omarchy-base.packages`).

- **keybindings** - `~/.config/hypr/bindings.lua`, heavily customized.
- **hyprland** - `input.lua`, `looknfeel.lua`, `autostart.lua` (differ from
  defaults), plus `hyprland.lua`, `hyprsunset.conf`, `xdph.conf`,
  `.luarc.json`, `monitors.lua` (user-only files, no default to diff
  against).
  > `monitors.lua` names specific display outputs (e.g. `eDP-1`,
  > `HDMI-A-1`) - it's tied to this machine's exact monitor setup. Review
  > it after applying if the target PC has different displays.
  > `hyprland.lua` also contains a hybrid-graphics override (WLR_DRM_DEVICES
  > + GLX=mesa) that pins the NVIDIA dGPU to RTD3 sleep - see "System-level
  > power/thermal config" below. The by-path device paths are specific to
  > this machine's iGPU/DisplayLink layout; review after applying on
  > different hardware.
- **environment.d** - `~/.config/environment.d/hybrid-graphics.conf` sets
  `WLR_DRM_DEVICES` and `__GLX_VENDOR_LIBRARY_NAME=mesa` before Hyprland
  starts (wlroots reads WLR_DRM_DEVICES at backend init, before config parse,
  so setting it in hyprland.lua alone is too late). This is what actually
  lets the NVIDIA dGPU enter D3cold/RTD3 when idle.
- **theme** - a hand-made theme, `omarchy-wallpaper` (currently active),
  plus two more wallpaper-derived themes, `pexels-jplenio-2080960` and
  `pexels-simon73-1323550`. (A 4th entry, `aether`, is a symlink created by
  the `aether` package itself, not a customization - excluded.)
- **barconfig** - `~/.config/omarchy/shell.json`: transparent bar, added/
  reordered bar widgets, 2 plugin design overrides, and `omarchy.audio` /
  `omarchy.lock` disabled (both superseded by third-party replacements
  below). `omarchy-menu.jsonc` and all hook scripts matched the defaults -
  nothing to capture there.
- **plugins** - 15 third-party shell plugins (see `plugins.txt`), each
  reinstallable from its git source with `omarchy plugin add`.
- **gloview** - the GloView Hyprland overview plugin, installed from the AUR
  (`gloview-git`) so its `.so` lands at `/usr/lib/gloview.so`, where
  `hyprland.lua` loads it at config-parse time. Not an omarchy shell plugin -
  it's a compiled C++ compositor plugin, so it's installed with `yay`, not
  `omarchy plugin add`.
- **dotfiles** - `.bashrc` (adds AUR-scan integration - see note below),
  `~/.config/git/config`, `~/.config/starship.toml`, `~/.config/btop/btop.conf`,
  `~/.config/mise/config.toml`. `.bash_profile` and the terminal emulator
  configs (alacritty/foot/kitty/ghostty) matched stock defaults - the
  terminal configs are regenerated by the theme system, not hand-edited -
  so they're excluded.
- **packages** - 13 default Omarchy packages that were removed on this
  machine (see `packages-removed.txt`): `chromium`, `libreoffice-fresh`,
  `localsend`, `moonlight-qt`, `nvim`, `obs-studio`, `obsidian`, `omacalc`,
  `omacut`, `omawrite`, `omarchy-nvim`, `pinta`, `xournalpp`.

`omarchy-other.packages` (hardware-conditional packages: nvidia/asus/dell/
apple/etc. drivers) was deliberately excluded from removal-detection - it
mixes universal and vendor-specific entries, so an absent package there
could just mean "wrong hardware", not "removed by you".
- **install** - packages added on this machine beyond the Omarchy defaults,
  split into `packages-added.txt` (official Arch repos) and
  `packages-aur.txt` (AUR, installed with `yay`): zen-browser, vscode
  (Microsoft proprietary `visual-studio-code-bin`), onlyoffice, discord,
  stirling-pdf (desktop wrapper `stirling-pdf-desktop-bin`), termix,
  element-desktop, tokodon, microsoft-edge, vacuumtube, ytmdesktop,
  nextcloud-client, opencode, kubectl, helm, ansible, docker, terraform,
  kdeconnect, tailscale, displaylink (AUR; builds the `evdi` DKMS kernel
  module - requires matching `linux-headers` + `dkms`). After installing,
  it also adds the current user to the `docker` group and enables+starts
  the `docker`, `tailscaled`, and `displaylink` services so non-root
  `docker` and the VPN/display daemons work (log out/in for the docker
  group change to take effect).
- **webapps** - removes the Omarchy web app launcher entries (Discord,
  WhatsApp, YouTube, Google Maps/Contacts/Messages/Photos, X, Zoom, HEY,
  Basecamp) from `~/.local/share/applications/`. These are installed by
  Omarchy's `omarchy webapp install` / menu "Web App" action and show as
  app icons in the launcher; this category deletes each one (plus its
  downloaded icon) so they no longer appear. The system templates in
  `/usr/share/omarchy/applications/` are left in place (not on the launcher
  search path) so `omarchy webapp install` still works if you want one back.

## Layout

```
omarchy-setup/
  apply.sh              the reapply script
  README.md
  plugins.txt           id <TAB> git-url <TAB> enable, one per line
  packages-removed.txt  one package name per line
  packages-added.txt    official-repo packages to install, one per line
  packages-aur.txt      AUR packages to install, one per line
  files/                snapshotted files, mirroring their path under $HOME
  gui/                  the setup wizard (GTK4 + libadwaita)
    wizard.py           the wizard app
    run.sh              launcher (called by apply.sh with no args)
    omarchy.css         base CSS; theme colors injected at runtime
```

## Usage

```bash
./apply.sh                 # launch the setup wizard GUI (interactive)
./apply.sh --cli           # interactive yes/no per category (terminal)
./apply.sh --all           # apply every category, no prompts
./apply.sh --only plugins,theme   # apply just the named categories
./apply.sh --myconfig ~/omarchy-config.json  # apply from a saved config
./apply.sh --list          # show category names/descriptions
```

With no arguments in a graphical session, `apply.sh` launches the setup wizard
GUI (`gui/wizard.py`). On a headless/SSH session (no `WAYLAND_DISPLAY` or
`DISPLAY`), or if `python3` is absent, it falls back to the `--cli` terminal
flow.

Categories always run in a fixed order regardless of selection order, since
later ones depend on earlier ones (e.g. the bar config references plugin
IDs that must already be installed):

`packages -> install -> webapps -> plugins -> theme -> gloview -> hyprland -> keybindings -> dotfiles -> barconfig`

Every file write backs up an existing destination first
(`<file>.bak.<unix-timestamp>`) - nothing is silently overwritten.

- **packages**: removes each package with plain `pacman -R` (not `-Rns`),
  so shared dependencies aren't cascade-removed on a machine with a
  different package set. To clean up any now-unused dependencies
  afterward: `pacman -Qtdq` (review the list, then `pacman -Rns -` the ones
  you don't want).
- **install**: installs `packages-added.txt` via `sudo pacman -S --needed`
  and `packages-aur.txt` via `yay -S --needed` (skipped if `yay` is absent).
  `--needed` makes it idempotent - already-installed packages are skipped.
  Also adds the current user to the `docker` group and enables+starts the
  `docker`, `tailscaled`, and `displaylink` services when their owning
  packages are installed (idempotent).
- **webapps**: deletes every `~/.local/share/applications/*.desktop` whose
  `Exec` launches a web app (`omarchy-launch-webapp` / `omarchy-webapp-handler`)
  plus its icon, then refreshes the desktop database. Idempotent - a no-op
  when no web app launchers are present.
- **plugins**: skips any plugin whose directory already exists under
  `~/.config/omarchy/plugins/`.
- **gloview**: installs `gloview-git` from the AUR via `yay` when
  `/usr/lib/gloview.so` is missing, then reloads Hyprland so the plugin loads
  at config-parse time. Requires the `yay` AUR helper; skipped if already
  installed.
- **hyprland**/**keybindings**: runs `hyprctl reload` + `hyprctl
  configerrors` afterward if a Hyprland session is detected (skipped
  quietly otherwise, e.g. running before first login).
- **barconfig**: runs `omarchy restart shell` afterward.

## Setup wizard GUI

The wizard (`gui/wizard.py`, GTK4 + libadwaita) is a 4-step interactive
configuration tool styled to match the active Omarchy theme (colors are read
at runtime from `colors.toml`).

1. **My Defaults** - all 10 categories as toggle rows, pre-enabled. This is
   the opinionated setup - your pre-configured defaults from this machine.
   Select all / none helpers provided.
2. **Plugins** - searchable list of every Omarchy shell plugin (merged from
   `omarchy-plugin-catalog` + `omarchy plugin list --json`), with name, id,
   kind badges, first-party tag, and an enable toggle. The 15 `plugins.txt`
   defaults are pinned to the top. A git-URL entry lets you add new plugins.
3. **Packages** - your opinionated package defaults from `packages-added.txt`,
   `packages-aur.txt`, and `packages-removed.txt` are listed at the top with
   pacman / AUR / removed badges and a toggle each (default on; toggling off
   skips that package). Below that, search official Arch repos and the AUR
   (toggleable) with repo badges (`extra`/`core`/`multilib` for pacman, `aur`
   highlighted in the accent color) to add extra packages.
4. **Review & Save** - summary of selected categories, plugin changes (delta
   vs current state), and extra packages. "Save config…" writes a JSON file;
   "Apply now" saves then runs `apply.sh --myconfig <file>` in a terminal.

Browsing and searching are read-only - nothing changes the system until you
choose to save and apply.

### JSON config schema (`--myconfig`)

```json
{
  "categories": ["packages", "install", "plugins", "theme", "hyprland", "…"],
  "plugins": {
    "enable":  ["id", "…"],
    "disable": ["id", "…"],
    "add": [{"id": "", "url": "https://github.com/…/plugin.git", "enable": true}]
  },
  "packages": { "pacman": ["pkg"], "aur": ["pkg"] },
  "configured_packages": {
    "added":   ["discord", "tokodon", "…"],
    "aur":     ["zen-browser-bin", "…"],
    "removed": ["chromium", "nvim", "…"]
  }
}
```

- `categories` selects which `apply_*` functions run (in fixed order).
- `plugins.enable`/`disable` are applied via `omarchy plugin enable/disable`
  after the `plugins` category; `add` via `omarchy plugin add <url> [--enable]`.
- `packages.pacman`/`aur` are extra packages from the search page, installed
  after the `install` category via `pacman -S --needed` / `yay -S --needed`.
- `configured_packages` lists which packages from `packages-added.txt`,
  `packages-aur.txt`, and `packages-removed.txt` to actually process — only
  the packages listed here are installed/removed, so toggling a package off in
  the wizard omits it. When absent, all packages from the text files are used
  (backward compatible with configs generated before this field existed).

To generate a default config without the GUI (e.g. over SSH):

```bash
./gui/run.sh --print-json > ~/omarchy-config.json
```

## Notes

- `.bashrc` sources `/usr/share/aur-scan/integration.bash` if present. This
  comes from the separate `aur-scanner` package (AUR PKGBUILD security
  scanning for `paru`/`yay`) - install it if you want that behavior; the
  line is a no-op guard if the package isn't present.
- No secrets are involved here (git config only has name/email) - nothing
  needs to be vaulted or encrypted.

## System-level power/thermal config (not in this repo)

The following optimizations live outside `~/` (system files) so they're not
snapshotted here. They were tuned for a Dell Precision 5550 (i7-10850H +
NVIDIA Quadro T1000 Mobile, Optimus hybrid). Reapply manually on a fresh
install or different machine:

- **NVIDIA dGPU RTD3** - `/etc/modprobe.d/nvidia.conf` adds
  `NVreg_DynamicPowerManagement=0x02` (fine-grained runtime D3) and
  `NVreg_PreserveVideoMemoryAllocations=1`. After editing, rebuild the
  initrd/UKI (this system uses Limine + UKI: `sudo limine-update`).
  Enable `nvidia-suspend`, `nvidia-hibernate`, `nvidia-resume` services.
- **NVIDIA PCI runtime PM** - `/etc/udev/rules.d/99-nvidia-runtimepm.rules`
  sets `power/control=auto` for the NVIDIA PCI device (the default
  `60-autosuspend.rules` sets it to `on`, blocking runtime suspend).
  Without this, DPM=0x02 alone won't suspend the dGPU.
- **iGPU + PCIe power saving** - `/etc/limine-entry-tool.d/power-save.conf`
  appends `i915.enable_dc=2 i915.enable_fbc=1 i915.enable_psr=2
  pcie_aspm=powersave` to the kernel cmdline. Regenerate with
  `sudo limine-update`.
- **CPU thermal (battery-biased)** - `/etc/udev/rules.d/99-tcc-offset.rules`
  + `/usr/local/bin/apply-tcc-offset` set the Intel TCC Offset to 8 on
  battery (throttle ~92C) and 0 on AC (full performance). PPD stays on
  `performance` on AC, `power-saver`/`balanced` on battery.
- **prime-run** - `/usr/local/bin/prime-run` wraps a command with PRIME
  render-offload env vars so the dGPU wakes on demand: `prime-run <app>`.
- **i8kutils fan control** - attempted but reverted: the Precision 5550's
  EC refuses software fan writes even with `dell_smm_hwmon restricted=0
  ignore_dmi=1 force=1`. Fans stay under BIOS control.

## Keeping this up to date

There's no automated "collect" script - if you customize further, manually
re-copy the changed file(s) into `files/` (or the theme directory into
`files/.config/omarchy/themes/`) and update `plugins.txt` /
`packages-removed.txt` as needed.
